# FR-11: присутність та удар у Wokwi

Виконано один короткий окремий дослід ELF SHA256 `58e5ab7fd10281b0df4a39b6f53b9b3df29d12f2352092f8791329d26027c54c`. Два окремі тестові компоненти о 5 с симулятора одночасно встановили PA1 HIGH і змінили значення X моделі регістрів MPU6050 з 0 до 2 g, залишивши Z = 1 g. Проєктний поріг різниці векторів — понад 1 g. Дослід не є перевіркою фізичних сенсорів або всіх фаз і режимів.

D0/D1 — SCL/SDA; D2/D3 — UART TX/RX; D4 — вхід PA1; D5 — маркер зміни регістрів тестового I²C-компонента; D7 — реакція policy. Дані VCD підтверджують два фронти на 5 с, кадри 0/0/1 g до та 2/0/1 g після і UART. У CONTROL `BODY_SHOCK` має WARN і `USER_NEAR` INFO. Від спільного стимулу до кінця рядка відповідно 14,379 та 38,511 мс, обидва менше 200 мс. Після подій RXDIAG не повідомив помилок, drop або armfail. `verification.json` містить конкретні VCD-моменти й SHA256. Це один позитивний сценарій FR-11, а не доказ довільних навантажень.

`uart.raw` — сирий запис UART, `fr11.vcd.gz` — безвтратний стиснутий VCD. Схема, джерела і WASM тестових моделей — `tools/lab3-fr11/workspace`. Для перевірки розпакувати VCD у окреме місце і виконати:

```sh
gzip -dc docs/metrics/lab3-fr11-20261101/fr11.vcd.gz > /tmp/kioskguard-fr11.vcd
python3 tools/lab3-fr11/verify.py /tmp/kioskguard-fr11.vcd docs/metrics/lab3-fr11-20261101/uart.raw
```

Попередні S1/S2/S3 не повторювалися; їхні результати та помилка audit Flash — окремо в `../lab3-observed-20261101/`.
