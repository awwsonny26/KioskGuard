# Захвати ЛР3

`kioskguard-lr3-current.vcd` є власним негативним pilot збірки `a86a7675f1c02054`, отриманим 28.10.2026. BOOT та початкові SELFTEST присутні, але подальша передача UART та інтервали задач деградують; `stats` у RX не отримав TX-відповіді. Це не завершений S1/S2/S3 і не вимір чистого CPU. Первинний запис з ELF/HEX і SHA256 збережений також у локальному Lab03/Work. Зображення архітектури описує попередній TIM3/WFI варіант, а не поточний SysTick/polling. Історичні записи ЛР2 лежать окремо у `docs/lab2/captures` і не підтверджують нову прошивку.

Поточний стенд ЛР3: D0=PA6 IMU, D1=PA8 audit, D2=PA2 TX, D3=PA3 RX, D4=PA1 PIR, D5=PA4 ADC, D6=PA5 heartbeat, D7=PA7 реакція policy на новий PIR HIGH. Канали D0/D1/D7 відрізняються від ЛР2. GND спільний.

Wokwi зберігає VCD за активним `wokwi.toml`; CAPABILITY1 використовує окремий `kioskguard-capability1.vcd`. Перед новим запуском зберегти попередній запис з назвою сценарію та manifest. `tools/trace_metrics.py` читає лише справжній VCD зі шкалою 1 нс. Файл зі штучно побудованим сигналом не є доказом.

Поточний кандидат не виводить STAT adc, тому ширину D5 неможливо зіставити з такою статистикою. Відстані D4→D7 і D4→кінець EVENT мають різні кінцеві точки. Для окремого FR-11 карта каналів та I²C-модель наведені в `../metrics/lab3-fr11-20261101/README.md`.
