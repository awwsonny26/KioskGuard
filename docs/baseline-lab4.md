# Базова лінія KioskGuard для ЛР4

Наведена нижче історична серія належить bare-metal прошивці `candidate-poll-tree-abf27f5853950696`, ELF SHA256 `58e5ab7fd10281b0df4a39b6f53b9b3df29d12f2352092f8791329d26027c54c`; її образ та джерела збережено у [результатах](metrics/lab3-observed-20261101/README.md). Поточна `make build` відтворює інший вимірювальний ELF `candidate-spans-20261101`, SHA256 `093897f8f59176f5ad30b271edb3f85f949fd2e511e66d8acfc195ac1d282cf2`; [його S1/S3](metrics/lab3-spans-20261101/README.md) не змішуються з таблицею старого ELF. Плата Nucleo-C031C6, Ubuntu 24.04, Docker, STM32 HAL, Wokwi. RTOS не реалізовано. `make version` змінює ідентичність образу.

| Сценарій | Підтверджений результат | Що повторити на ЛР4 |
|---|---|---|
| S1 | 120 с MCU, 241 SAMPLE, без команд | Те саме опитування і канали VCD |
| S2 | Безперервні 3600000 мс MCU; audit failed=1 committed=0 | Той самий потік команд і явний контроль commit, не приховуючи відмову |
| S3 | 45 синтетичних HIGH у завершених export-вікнах; D4→кінець TX 15,883–61,378 мс | Той самий seeded fixture, export, команди і метод VCD |
| FR-11 | Один одночасний GPIO + I²C стимул, дві події за 14,379/38,511 мс | Однакова тестова схема і межі вимірювання |
| I²C | Програмний NACK; ERROR 26,219 мс, RECOVERED 996,217 мс | Те саме адресне внесення та окрема фізична перевірка |
| Періоди | Режими 20/10/5 мс; абсолютна точка зламу не знайдена | Ті самі режими, потім додаткові навантаження з чітким критерієм |

Цифри таблиці — Wokwi для попереднього ELF; VCD й MCU перебувають в одному симуляторі. Новий ELF дав спостережені піки stack/heap у S1/S3, але повний CPU/WCET, фізичні датчики і power-loss не виміряно. Статичні linker reservations і host byte-cut модель не заміняють цих вимірів. Зберігайте сирі дані й точні версії для кожного нового експерименту. [Обмеження](limitations.md).
