# Базова лінія KioskGuard для ЛР4

Зафіксована bare-metal прошивка `candidate-poll-tree-abf27f5853950696`, ELF SHA256 `58e5ab7fd10281b0df4a39b6f53b9b3df29d12f2352092f8791329d26027c54c`. Плата Nucleo-C031C6, Ubuntu 24.04, Docker, STM32 HAL, Wokwi. RTOS тут не реалізовано. Той самий контрольний образ та джерела збережено у [результатах](metrics/lab3-observed-20261101/README.md). `make build` не перезаписує version.h; окремий `make version` змінює ідентичність і не відтворює досліджений ELF.

| Сценарій | Підтверджений результат | Що повторити на ЛР4 |
|---|---|---|
| S1 | 120 с MCU, 241 SAMPLE, без команд | Те саме опитування і канали VCD |
| S2 | Безперервні 3600000 мс MCU; audit failed=1 committed=0 | Той самий потік команд і явний контроль commit, не приховуючи відмову |
| S3 | 45 синтетичних HIGH у завершених export-вікнах; D4→кінець TX 15,883–61,378 мс | Той самий seeded fixture, export, команди і метод VCD |
| FR-11 | Один одночасний GPIO + I²C стимул, дві події за 14,379/38,511 мс | Однакова тестова схема і межі вимірювання |
| I²C | Програмний NACK; ERROR 26,219 мс, RECOVERED 996,217 мс | Те саме адресне внесення та окрема фізична перевірка |
| Періоди | Режими 20/10/5 мс; абсолютна точка зламу не знайдена | Ті самі режими, потім додаткові навантаження з чітким критерієм |

Цифри — Wokwi; VCD й MCU перебувають в одному симуляторі. CPU/WCET, фактичні stack/heap, фізичні датчики і power-loss не виміряно. Статичні linker reservations і host byte-cut модель не заміняють цих вимірів. Зберігайте сирі дані й точні версії для кожного нового експерименту. [Обмеження](limitations.md).
